# `autan plan`

`autan plan` checks a case against its mesh before you reserve a GPU. It shows the condition of every boundary and cell zone and where it comes from ([boundary resolution](../contracts/case-schema.md#boundary-resolution)), reports coded [diagnostics](errors.md) and estimates device memory.

```text
autan plan CASE --mesh-info MESHINFO [--gpus N] [--device-kind cpu|cuda|hip] [--json]
```

It exits with 1 when it finds an error. The SDK does not call the mesh readers yet: write the MeshInfo with `autan-mesh-info --json --scale S MESH`, S the case's metres per mesh unit, adding `--ranks N` for a run on N ranks (and `--groups lines` for a steady CPU run with the `lines` solver), and pass it with `--mesh-info` (`E0210` for a MeshInfo written for another run). `plan` compares its `source.sha256` with the hash of the mesh file (`E0203`) and warns when the file is absent (`W0205`). [Check a case before you run it](../guides/check-a-case.md) walks through the output.

## Memory model `autan.memory/2`

The estimate is what one rank allocates at its peak, on the host and on its device, by component; `--gpus` is the number of ranks and `--device-kind` (`cpu`, `cuda`, `hip`, default `cuda`) their device. `bytes_per_gpu` is a rank's host plus device bytes, which share one pool on a unified-memory device such as the GB10, and `bytes_total` that times the ranks. `autan prepare` writes a rank's figures into the solver input (`memory`), and `autan-run` refuses to start a run that does not fit (`E0711`).

Each component counts what the code allocates, listed by the lane that owns it and summed here (#325). Notation, per rank: C cells, F faces, F_i interior faces, F_b boundary faces, K = 2F_i + F_b, S gradient stencil entries (`counts.stencil_entries`; C includes a single rank's `counts.periodic_ghosts`, each with at most `max_faces_per_cell` faces; on several ranks C, F, F_i and S are those of the largest rank of the MeshInfo's `partition`, owned cells and ghosts), n solved equations, s = 4 bytes in `fp32+acc64` and 8 in `fp64`; N nodes, P face nodes (`counts.face_nodes`) and the cell and face counts of the whole mesh where marked *global*.

| Component | Where | Bytes |
|---|---|---|
| `runtime` | host | the process itself on every rank (binary, libraries, MPI, the hashing buffer): 26 MiB, the largest `VmHWM` of `autan-run` on the 27-cell `tests/data/mesh/hex/polyMesh` case on 1 and 2 ranks (26 431 488 B, Release, spark-5359), rounded up to the next MiB |
| `solver input`, `solver input setup` | host | the solver input as `autan prepare` writes it, at most: 6 bytes per byte of the case's TOML (escaped in JSON, its mesh path counted at 4 096 bytes however the case names it); the MeshInfo, indented, plus 4 bytes a line; each zone's name and resolved condition or medium as JSON plus 1 KiB (and 6 × 4 096 bytes for an `oracle-state` file's path); each monitor's name and the names of the zones it matches plus 1 KiB; a point vortex's wall names; three paths at 6 × 4 096 bytes; and 64 KiB. The runtime keeps the case's name and text, and reads and parses the document once, at most 40 bytes of document per byte |
| `mesh` | host | the global mesh 24N + 16F + 4P + 12F_i + 4F_b + 20C, its FP64 geometry 56F + 32C, colourings 12C, all *global*: every rank keeps them |
| `mesh setup` | host | the reader's form and the MeshInfo pass, about the mesh and its geometry again, which the allocator keeps resident |
| `partition` | host | several ranks: the rank's share of the mesh and geometry, and 9F face keys |
| `mesh reading` | host | while the file is read, beyond the mesh it returns, what each reader holds at its peak, derived from its code (« CFD - Noyau maillage »'s inventory), with N_s = `counts.source_nodes` (the nodes the file holds, unreferenced ones included), K = 2F_i + F_b and S = `source.bytes`, each text read once at its size: Gmsh S + 60N_s − 24N − 8C + 52F + 20P + 512 KiB (its batch of element-block entities); Fluent S + 53N_s + 20C + 16P + 45F + 256 KiB (16 B for each of at most 16 384 fluid and solid zone records); CGNS the larger of its element path (48N_s − 24N, 64 B plus the connectivity block per cell by shape, 112 B per boundary face, labels 64 B per boundary face and per cell, 4C + 52F + 16P) and its NGON path (24N_s + 172F + 4P + 152C + 64F_b − 4F_i), each with its sections read in chunks (1 MiB + 32 KiB of buffers) and 24 B per element and one more for the runs of points and edges a section skips, plus 1 MiB + 16 KiB per node of the tree (`source.cgns_nodes`, at most 16 384, `E0133`), the 1 MiB of data `cg_open` reads at once (`E0133` beyond), 8 B per `source.point_list_ids` and a 1 MiB chunk (the ids its point lists name), `source.descriptor_bytes` (`cg_open` loads every descriptor and holds it until close), `source.filtered_bytes` (one filtered dataset inflated at a time beside its destination), 40 times `source.zone_names_bytes` (the reader parses ZoneNames) and HDF5's default caches, 12 MiB + 64 KiB ([mesh.md](../contracts/mesh.md#memory-of-a-cgns-read)); polyMesh S + 52N_s − 24N + 33F + 8F_i + 4P + 8C; Gmsh and CGNS periodic matching adds 149N_s and 113 B per paired face |
| `renumbered mesh` | host | in RCM order (`quality.lines.order`, the runtime's default) the renumbered copy of the global mesh, as `mesh` without its geometry, and the order and face and point maps 4C + 5F + 4N |
| `solution output` | host | rank 0 gathers 8C *global* bytes per field, and the writer copies them, with the coordinates 24N and the 64-bit connectivity 8 max(F, C) + 8 max(P, K) *global*: the n + 1 primitive fields and their means, the restart's n conserved, n + 1 average sums and their weight, the steady solver's n + 5 values, and one circulation per point-vortex condition |
| `start` | host | a run that starts from a previous one (`autan run --start`) reads its solution on every rank and takes the rank's share: 8(C *global* + C) bytes per field read, every written field for `continue`, the n + 1 primitive fields for `warm`; and the descriptors its writer wrote, unfiltered, which `cg_open` holds until close (`E0707` beyond them): run metadata of at most 64 KiB, also copied and parsed (42 × 64 KiB in all), zone names of 25 600 bytes per zone and one more, 4 096 bytes per periodic zone, HDF5's caches, and `cg_open`'s tree at 1 MiB + 16 KiB a node for the 16 384 nodes the runtime accepts in a start file, with the 1 MiB of data it reads at once ([mesh.md](../contracts/mesh.md#memory-of-a-cgns-read)) |
| `state files`, `face states`, `manufactured solution` | host | each file of the case read once at its size S: an initial state 2S (its text and strings) + 16 KiB + N + 1 KiB + 266 bytes per row streamed and paired + 160 bytes per cell; face states 2S + 16 KiB + N + 1 KiB + 128 bytes per row + 1 200 per zone + 40 per face of the oracle zones, which a run keeps; 16 KiB is a string at its 4 096-byte bound ([case-schema.md](../contracts/case-schema.md#free-texts)), which the text, the parser's token buffer (twice) and the key or value it builds hold, and N the bytes of the file's member names, which an object copies once more while it grows; a manufactured solution's text, read into a buffer of the contract's 1 MiB + 1 byte, and its compiled expressions, kept for the run (at most one 32-byte node per byte of text, in vectors up to twice that: 64 S), and its parse at most 40 bytes of document per byte of text while those vectors grow (32 S more) |
| `physics` | host | packed geometry 8(16F + 4C + 3S), stencil 8C + 4S, state, primitives, limiters, gradients and boundary data in s, solution, stages (a CPU run only), residual in 8 bytes |
| `physics setup` | host | the constructor's packed geometry 8(25F + 4C + 4K) and the stencil's twins and FP64 weights 32S, freed when it returns |
| `device mesh host`, `device setup` | host | on `cuda` and `hip`: the face colourings 4F DeviceMesh keeps; and its setup, with the packed geometry 8(25F + 4C + 4K) it holds until `release_host` after bind, plus the largest of its phases: construction 8K + 8F, the weights' upload 48S + nCs (its FP64 weights and the physics' copy), bind 24S and one staged chunk of 8 MiB |
| `physics device`, `device context` | device, host | on `cuda` and `hip`: the same state, topology, stencil and geometry on the device; 512 MiB for the device context |
| `jacobian` | host | steady runs on `cpu` (a device run solves explicitly): face and cell Jacobians in s, the block matrix 8n²(C + 2F_i) |
| `multigrid`, `lines`, `gauss-seidel` | host | the case's `linear_solver`: the levels below the finest as `quality.multigrid` gives them, 1000 bytes per node and 410 per edge, and the coarsest level's dense LU, 8u² + 8u bytes for its u = 5C_L unknowns (C_L its cells, 5 equations each) when u ≤ 1000; line smoothing for the MeshInfo's `quality.lines.cells` on the finest level (the multigrid's own count, for the cell order it states) and for every coarse cell when there are lines; the lines built on the whole mesh at setup; the inverse diagonal blocks. Building the multigrid hierarchy holds, beyond what it keeps, the larger of its isotropic loop, 96F_i + 284C + 72F_b, and its coarse-edge build, 69F_i + 48F_1 + 296C + 156C_1 + 144F_b (F_1 and C_1 the first coarse level's edges and cells), measured within those bounds (×0.54 to ×0.80) on 45 meshes up to DPW4 ([setup-memory.md](../design/setup-memory.md)) |

The blocks of the linear solvers are counted for n = 5 and scaled by n²/25. The figures were calibrated on the CPU against measured host peaks (`memory` event of the log, results.md): the multigrid and lines terms on NACA 0012 256², a 48³ hexahedral manufactured solution and the TMR flat plate 137×97 (within ×1.04 to ×1.20 of the measured solver memory), the mesh terms on a 1.17 M-cell tetrahedral mesh. The estimate is for the cell order the MeshInfo states (`quality.lines.order`); a run with another order (`AUTAN_CELL_ORDER`) may form slightly different lines. The model is checked on other cases with two criteria fixed before measuring: **safety**, the estimate at least the measured peak (a refusal must never let through a run that does not fit), and **precision**, at most 1.25 times it. On tet n024, polyhedral n024, NACA 0012 1024² on one and two ranks and the DPW4 CRM grid on a GB10 (Release, spark-5359), declared before measuring, on a 216-cell mesh, a Gmsh file carrying large skipped sections, and mesh and state files padded to 64 MiB (`py/tests/test_memory_adversarial.py`), safety holds on every case: the estimate is 1.06 to 2.07 times the measured peak on the CPU cases and 1.27 times an upper bound of DPW4's peak on a GB10; precision holds only on three padded cases (#370). It is conservative, so `autan-run` may refuse a run that would fit; `--allow-oversubscription` starts it, explicitly and logged (`W0712`).
