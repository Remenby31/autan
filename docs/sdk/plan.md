# `autan plan`

`autan plan` checks a case against its mesh before you reserve a GPU. It shows the condition of every boundary and cell zone and where it comes from ([boundary resolution](../contracts/case-schema.md#boundary-resolution)), reports coded [diagnostics](errors.md) and estimates device memory.

```text
autan plan CASE --mesh-info MESHINFO [--gpus N] [--device-kind cpu|cuda|hip] [--json]
```

It exits with 1 when it finds an error. The SDK does not call the mesh readers yet: write the MeshInfo with `autan-mesh-info --json --scale S MESH`, S the case's metres per mesh unit, adding `--ranks N` for a run on N ranks (and `--groups lines` for a steady CPU run with the `lines` solver), and pass it with `--mesh-info` (`E0212` for a MeshInfo written for another run). `plan` compares its `source.sha256` with the hash of the mesh file (`E0203`) and warns when the file is absent (`W0205`). [Check a case before you run it](../guides/check-a-case.md) walks through the output.

## Memory model `autan.memory/2`

The estimate is what one rank allocates at its peak, on the host and on its device, by component; `--gpus` is the number of ranks and `--device-kind` (`cpu`, `cuda`, `hip`, default `cuda`) their device. `bytes_per_gpu` is a rank's host plus device bytes, which share one pool on a unified-memory device such as the GB10, and `bytes_total` that times the ranks. `autan prepare` writes a rank's figures into the solver input (`memory`), and `autan-run` refuses to start a run that does not fit (`E0711`).

Each component counts what the code allocates, listed by the lane that owns it and summed here (#325). Notation, per rank: C cells, F faces, F_i interior faces, F_b boundary faces, K = 2F_i + F_b, S gradient stencil entries (`counts.stencil_entries`; C includes a single rank's `counts.periodic_ghosts`, each with at most `max_faces_per_cell` faces; on several ranks C, F, F_i and S are those of the largest rank of the MeshInfo's `partition`, owned cells and ghosts), n solved equations (for Spalart-Allmaras the flow's 5, its ν̃ a scalar system of its own, below), V, B and Q the vertex stencil, band and boundary-fit entries (`counts.vertex_stencil_entries`, `band_entries`, `boundary_fit_entries`, or the rank's in `partition`), s = 4 bytes in `fp32+acc64` and 8 in `fp64`; N nodes, P face nodes (`counts.face_nodes`) and the cell and face counts of the whole mesh where marked *global*.

The blocks of the linear solvers are counted for n = 5 and scaled by n²/25. The figures were calibrated on the CPU against measured host peaks (`memory` event of the log, results.md): the multigrid and lines terms on NACA 0012 256², a 48³ hexahedral manufactured solution and the TMR flat plate 137×97 (within ×1.04 to ×1.20 of the measured solver memory), the mesh terms on a 1.17 M-cell tetrahedral mesh. The estimate is for the cell order the MeshInfo states (`quality.lines.order`); a run with another order (`AUTAN_CELL_ORDER`) may form slightly different lines. The model is checked on other cases with two criteria fixed before measuring: **safety**, the estimate at least the measured peak (a refusal must never let through a run that does not fit), and **precision**, at most 1.25 times it. On tet n024, polyhedral n024, NACA 0012 1024² on one and two ranks and the DPW4 CRM grid on a GB10 (Release, spark-5359), declared before measuring, on a 216-cell mesh, a Gmsh file carrying large skipped sections, and mesh and state files padded to 64 MiB (`py/tests/test_memory_adversarial.py`), safety holds on every case: the estimate is 1.06 to 2.07 times the measured peak on the CPU cases and 1.27 times an upper bound of DPW4's peak on a GB10; precision holds only on three padded cases (#370). On viscous runs (X2p manufactured solutions, fp64, CPU, 20 steps, spark-75d6) the estimate is 1.72 times the measured peak on hybrid n048 (laminar), 1.76 on hexahedra n096 (laminar) and 1.89 on the Cartesian (n, 4n, n) n048 (Spalart-Allmaras): the band's weights, built once while the boundaries are set, before the Jacobian and the linear solver exist, are counted on top of every component, and the fit at three rings where the run takes two (#542; a phase-aware peak is #559). It is conservative, so `autan-run` may refuse a run that would fit; `--allow-oversubscription` starts it, explicitly and logged (`W0712`).
