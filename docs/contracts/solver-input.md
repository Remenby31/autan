# Contract: solver input

The solver input is the document the SDK hands to the solver runtime `autan-run`: a case already planned against its mesh, every zone resolved, every value in SI except the mesh's own coordinates and `periodic[]`, which stay in the mesh file's units and which the runtime scales by `mesh.scale`. The runtime applies no other unit conversion, and no default or resolution rule of its own. Schema identifier: `autan.solver-input/1`; the JSON Schema is generated by `autan schema solver-input`.

Producer: `autan prepare` / `autan.solver_input.build` (owner: CFD - SDK & contrats), only after a plan without errors; `autan prepare` reports the plan's warnings on stderr. Consumer: `autan-run` (owner: CFD - Noyau maillage).

## Invocation

```text
autan-run --input solver-input.json --runs DIR [--stop-file PATH]
          [--memory-margin BYTES] [--allow-oversubscription]
```

`autan-run` creates `DIR/<run_id>/` as [results.md](results.md) specifies, writing `case.toml` (the `case.toml` text of the input, unchanged), `mesh-info.json` (the input's `mesh_info`), `run.json`, `history.jsonl` and `solution.cgns`, with `identity` and `run_id` computed from its own commit. It prints the run directory path on one line of stdout (rank 0 alone, on several ranks), and reads nothing on its standard input: it runs with it closed. With `--stop-file`, the run stops between two iterations once `PATH` exists, on every rank together, as for SIGINT: the way to stop a run started through an MPI launcher, which turns a signal into an abort. Before reading the mesh, every rank weighs `memory` against the memory its host can still give, less `--memory-margin` (default 2 GiB): the ranks of a host share its memory, and its devices in turn; on the CPU or a device whose memory is the host's (`cudaDevAttrIntegrated`, GB10), a rank's host and device shares come from one pool, the lower of `MemAvailable` and every cgroup limit (v2 or v1) on the process's cgroup and its ancestors, less its usage; in the process's own cgroup, its inactive page cache counts as available, at most up to the limit (`memory.stat` `inactive_file`, `total_inactive_file` on v1; without it, limit less usage), an ancestor's not, since a protected sibling may hold it; on a discrete device, the device share comes from the device's free memory. A run that does not fit is refused on every rank (`E0711`, exit 2); `--allow-oversubscription` starts it with `W0712`, the largest need and the least available memory of the ranks short of it, written to stderr before the mesh is read and kept in the run's log. A memory cgroup above the process that no mount shows has a limit the runtime cannot read: the check rests on what it could read, and `W0713` says so, written the same way (`cgroup_limit: "unknown"` in the data of `E0711` and `W0712` too). In a private cgroup namespace (`/proc/self/ns/cgroup` other than the initial namespace, the kernel's `PROC_CGROUP_INIT_INO`; no link means no namespaces) the cgroups above the namespace root are invisible: the data say `cgroup_scope: "namespace_root"` (`"host"` in the initial namespace), and when no limit is visible at all `W0713` names them as unseen. `W0712` and `W0713` are written before any rank reads the mesh, and `W0712` says `unknown` or `namespace_root` if any rank does.

| Exit | Meaning |
|---|---|
| 0 | The run ended `converged`, `completed`, `stopped` or `diverged`; the status is in `run.json`. |
| 1 | The run `failed`; `run.json` carries `E0704`. |
| 2 | The input cannot be run: invalid document (`E0705`, `data.path` names the key), not enough memory (`E0711`), mesh hash different from `mesh.sha256` (`E0203`), or no implementation of the physics, turbulence model, precision and device kind in this build, or of the case's media and zones ([runtime.md](runtime.md#registration)) (`E0706`). No directory is created; the diagnostics go to stderr as JSON in the shape of [case-schema.md](case-schema.md#diagnostics), with `fix` and `doc` taken from [`diagnostics.json`](diagnostics.json), as for every diagnostic the runtime writes. stderr holds one diagnostic per line: the warnings written before the refusal (`W0712`, `W0713`), then the error that refused the run, last. On several ranks each rank's lines keep that order, but a launcher that merges the ranks' streams may deliver one rank's warning after another rank's error, and a build without MPI started on several ranks writes its `E0146` from each process: read the refusal as the error, whichever line it is on. |
| 130 | Stopped by SIGINT, SIGTERM or the stop file; the run is finalized as `stopped` with its solution. |

## Document

Every table rejects unknown keys; every key is present, `null` where it does not apply, and every tag (`schema`, `kind`, `law`, `model`) is written. Units are SI: m, s, kg, K, Pa, rad. Values a key's neighbours make meaningless must be `null`, values they require must not be; the JSON Schema encodes these rules.

| Key | Content |
|---|---|
| `schema` | `"autan.solver-input/1"` |
| `case` | `name`; `sha256` the case hash; `toml` the exact text to write as `case.toml` |
| `mesh` | `path` absolute path of the mesh file or polyMesh directory; `sha256` expected mesh hash ([mesh-info.md](mesh-info.md)), checked by the runtime; `groups_sha256` the MeshInfo's `groups_source.sha256` (null without zone groups), which the runtime records in `run.json`; `scale` metres per mesh unit (the case's `mesh_unit`, to 15 significant digits: `0.0254` for `in`), > 0. The runtime multiplies every node coordinate and periodic translation by `scale` once, after reading the mesh and checking `periodic` against it, before any geometry: everything else is SI |
| `mesh_info` | the MeshInfo the plan used ([mesh-info.md](mesh-info.md)), as `autan-mesh-info` wrote it: its `source.sha256` equals `mesh.sha256` and its `source.bytes` the size of the mesh read (`E0203` otherwise) its `quality.lines.order` the cell order the run computes in and its `quality.lines.scale` `mesh.scale` (`E0705`). The runtime writes it as the run's `mesh-info.json` and never recomputes it |
| `precision` | `"fp32+acc64"` or `"fp64"` |
| `reproducibility` | The case's `physics.reproducibility`: `none`, `run` or `ranks` ([case-schema.md](case-schema.md#physics)) |
| `devices` | `kind` (`cpu`, `cuda`, `hip`) and `count`: the number of ranks, one device each (on `cuda` and `hip`, rank r takes the device r modulo the devices its node shows). The runtime refuses a launch with another number of ranks (`E0705` at `devices.count`). |
| `memory` | `{bytes_host, bytes_device}`: what one rank allocates at its peak on the host and on its device, the plan's estimate for these `devices` ([plan.md](../sdk/plan.md#memory-model-autanmemory3)). Before reading the mesh, the runtime refuses a run whose estimate exceeds the memory available to it minus a margin (`E0711`; on a unified-memory device or the CPU the two together) |
| `physics` | `kind` (`compressible`, `incompressible`); `flux` (`roe`, `hllc` or `ausm+up` for compressible physics, null otherwise); `turbulence`: `model`, `base` (DDES only: `sa` or `sst`), `wall_model` (WMLES only), `nu_tilde_ratio` (exactly for SA and DDES on SA), `intensity` and `viscosity_ratio` (exactly for SST and DDES on SST). DDES and WMLES require an unsteady `time`. |
| `freestream` | Closed state: `density` (kg/m³), `pressure` (Pa; 0 for incompressible), `temperature` (K; null for incompressible), `velocity` (m/s, mesh axes), `speed` (m/s), `viscosity` (dynamic, Pa·s); as given: `mach`, `re`, `ref_length` (m), `aoa` and `sideslip` (rad); turbulence state: `nu_tilde` (m²/s), `k` (m²/s²), `omega` (1/s), null when the model has none |
| `boundaries[]` | One entry per boundary zone with a condition (zones without faces and without condition are omitted): `zone` (MeshInfo name), `rule` (the index in the case's `boundaries` of the rule that gives the zone its condition, null when the mesh's type gives it, as `autan plan` shows), `kind` as in [case-schema.md](case-schema.md#boundaries) or `manufactured` (see `verification`), and its values, required for its kind and null otherwise: `inlet` takes `total_pressure` (Pa) and `total_temperature` (K); `velocity-inlet` takes `velocity` (m/s); `outlet` takes `static_pressure` (Pa); `oracle-state` takes `states = {path, sha256}`, the absolute path of its [face-state file](face-states.md) and the `sha256` of the case rule that applies to the zone, which the runtime checks (`E0420`, `E0422`) and pairs with the zone's faces by centroid (`E0421`); `wall` may take `temperature` (K, isothermal; null is adiabatic); `farfield` may take `point_vortex = {zones, center}`, the wall and slip zones its circulation comes from and its center (m) ([case-schema.md](case-schema.md#boundaries)); the other kinds take none. |
| `periodic[]` | The periodic pairs of the MeshInfo, `[]` without: `zones` (`[a, b]`) and `transform` (`{kind = "translation", vector}`, in mesh units), as in [mesh-info.md](mesh-info.md). The runtime checks them against the mesh it reads. Periodic zones are not in `boundaries[]`. |
| `cell_zones[]` | One entry per cell zone: `zone`, `initial` (see [initial state](#initial-state)), `medium`: `{kind = "ideal-gas", name, gas_constant (J/(kg·K)), gamma, prandtl, viscosity = {law = "sutherland", mu_ref (Pa·s), t_ref (K), s (K)} or {law = "constant", mu (Pa·s)}}`, `{kind = "constant-density-fluid", name, density, viscosity}` or `{kind = "solid", name, density, specific_heat (J/(kg·K)), conductivity (W/(m·K))}` |
| `time` | `{kind = "steady", max_iterations, residual_orders, linear_solver, coupled_turbulence, matrix_free, start_order, checkpoint}` (`linear_solver`: `multigrid`, `gauss-seidel` or `lines`; `coupled_turbulence` and `matrix_free` booleans; `start_order` `first` or `second`, [case-schema.md](case-schema.md#time)) or `{kind = "unsteady", steps, dt (s), cfl, average_from, checkpoint}` with exactly one of `dt` and `cfl` non-null and `average_from` null or below `steps`; `checkpoint` is `{seconds}` (in [60, 86400]) or `{iterations}` (≥ 1) |
| `monitors[]` | `{kind = "forces", name, every, zones (boundary zone names), ref_area (m²) or null, ref_length (m) or null, moment_center (m)}` |
| `initial_state` | `null`, or `{path, sha256}`: absolute path and SHA-256 of the case's [initial-state file](initial-state.md), which the runtime checks (`E0508` to `E0510`) and pairs with the fluid cells by centroid (`E0511`) before any directory exists; the physics starts every fluid cell from it. Given exactly when the case has `initial_state` with the same `sha256`, and never with `start`. |
| `verification` | `null`, or `{path, sha256}`: absolute path and SHA-256 of the `autan.mms/1` manufactured solution, checked by the runtime like the mesh (`E0206` on mismatch). Every boundary then has `kind = "manufactured"` and no value; without it, no boundary has that kind. The runtime takes everything the solution defines from it: exact boundary data, the source term and the auxiliary fields, such as the wall distance of RANS solutions, which replaces the geometric one. `verification.sha256` equals the case's in `case.toml`. |
| `start` | `null` (start from the freestream), or the previous run to start from: `{run, run_id, identity, mode, iterations, time, solution_sha256, file, residual_reference, woken}`. `run` is its absolute directory. `file` is the file read from it:
- `"solution"` (`solution.cgns`), for a run that ended `converged`, `completed` or `stopped` after at least one iteration;
- `"checkpoint"` ([checkpoint.cgns](results.md#checkpointcgns)), for any other run, which must then have one: `diverged`, `failed`, or still `running` (killed, or yet running, in which case its next checkpoint may replace the file and the start then fails `E0709`).

`iterations` and `time` are those of that file's state and `solution_sha256` is the SHA-256 of that file, both from one reading of it. For a `continue`, `time` is null when the case is steady and a number at least 0 when it is unsteady (`E0705`); the runtime takes it as given, without comparing it with the file's state. `residual_reference` and `woken` are given for a steady `continue` and for a `warm` start of a steady case from a steady run (`time` null), and are null otherwise ([case-schema.md](case-schema.md#time)); for a checkpoint they come from its `RunMetadata` `checkpoint`, and a `warm` start gives `woken` empty. The rest is copied from the run's `run.json`. The SDK has checked that the file conforms to the run's `run.json` (`E0707`, also for a run that ended or was killed before its first checkpoint), on the same mesh (`E0203`), and that the case matches the mode (`E0708`): `continue` keeps the previous case except its iteration or step budget, which exceeds the iterations done, and its checkpoint cadence; `warm` keeps the physics kind and the transported variables (DDES base model included). The runtime checks the file's hash (`E0709`), the mesh, physics and precision, and for a checkpoint that its `checkpoint.iteration` is `start.iterations` (`E0707`). It reads the state from that file (and `RestartState` when present), and with `continue` goes on counting iterations and physical time, measuring steady convergence against `residual_reference` (the residuals at iteration 1 of the original run) with the identically zero equations of `woken` no longer exempt ([case-schema.md](case-schema.md#time)); with `warm` it counts from 1 and, when `residual_reference` is given, measures steady convergence against it. |

The freestream closure is that of [case-schema.md](case-schema.md#freestream): with `re`, ρ∞ = Re μ(T∞) / (V∞ L) and p∞ = ρ∞ R T∞; with `pressure`, ρ∞ = p∞ / (R T∞); V∞ = M √(γ R T∞); R = 8.314462618 J/(mol·K) divided by the molar mass. Turbulence at an inlet uses the ratios of `physics.turbulence` with the inlet's local ν and speed, as [case-schema.md](case-schema.md#turbulence) defines.

## Initial state

Each cell zone starts from its case `initial` state when the case gives one, otherwise from the freestream pressure, temperature and velocity; either is closed with the zone's own medium, so zones of different gases or fluids start consistently. Turbulence values use the freestream speed as reference:

- fluid zone, `initial = {kind = "fluid", density, pressure, temperature, velocity, nu_tilde, k, omega}`: with p, T, V the zone's state: ideal gas ρ = p / (R_zone T); constant-density fluid ρ = its density, and p = 0 when the state is the freestream; ν = μ_zone(T) / ρ; `nu_tilde` = `nu_tilde_ratio` ν, k = 1.5 (`intensity` V∞)², ω = k / (`viscosity_ratio` ν), each null when the model has none;
- solid zone, `initial = {kind = "solid", temperature}`: T∞.
